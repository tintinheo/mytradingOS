## Bugs reproduced and fixed

1. `Number()` coercion admitted malformed provider values: an empty JSON array became volume zero; a one-element array became a seemingly valid numeric value. Browser and both server provider adapters were affected. Numeric strings such as hexadecimal and binary values also passed as financial data.
2. The server accepted any string beginning with a valid ISO date and discarded its suffix. Invalid suffixes could pass; an offset timestamp could map to a different trading session than the equivalent Unix timestamp. The browser had a separate coercive timestamp parser.

Four new regressions failed against the original source, including an integration check showing malformed primary data was accepted without triggering fallback. After the fix they pass without loosening their assertions.

## Implementation and files

- `public/lab/ohlcv-values.mjs`: shared strict scalar/date contract. Accept finite JSON numbers and explicitly decimal numeric strings (trimmed whitespace allowed); reject containers, booleans, null, blank strings and non-decimal string syntax. JSON numeric scientific notation remains a number after parsing; scientific notation encoded as a string is deliberately unsupported.
- `lib/ohlcv.ts`: both DNSE and CafeF normalizers use that contract before existing OHLC consistency, sorting and duplicate checks.
- `public/lab/core.mjs`: browser compact DNSE path uses the same value/date parsing. Date-only ISO and DD/MM/YYYY values name sessions; offset-qualified ISO instants and Unix seconds/milliseconds convert to UTC+07:00. Impossible dates, ambiguous timezone-free datetimes, invalid time components and trailing garbage are rejected. The adapters remain daily-history adapters, not intraday aggregation services.
- `lib/source-capture.mjs`: adapter version becomes `daily-capture-2026.10.06.1`, so new captured evidence identifies the changed normalization. Engine version stays unchanged: investment calculations were not changed. Old audit snapshots are not rewritten.
- `tests/ohlcv-contract.test.mjs`: invalid scalar types, accepted decimal values including legitimate zero volume, invalid dates, equivalent instants, normalized duplicate sessions, and acquisition/fallback/NO SIGNAL behavior with raw-hash preservation.
- README, CHANGELOG and in-app report: current status and limitations.

Pipeline remains status → Content-Type → bounded body → JSON → strict OHLCV/date contract → normalized series → freshness/reconciliation → analysis eligibility. If a primary fails the schema, existing distinct-provider capture runs; unverified fallback is quarantined. There is no automatic trust promotion.

## Remaining P0 acceptance gates

- Independent upstream lineage is still unverified. DNSE's alternate hostname is not a second source. Matching values alone do not establish independence.
- Reviewed historical exchange calendars, corporate actions and point-in-time VN100 membership remain required for intended historical periods; no historical records were invented or imported by this release.
- Authenticated live FPT and browser end-to-end validation were not performed. These are deterministic automated provider/client/service tests, not a live-provider health claim.
- This release rejects ambiguous date/numeric representations. If a provider introduces a new documented encoding, add an explicit mapping and regression rather than silently coercing it.
- Failure diagnostics remain client-relayed evidence, not server-signed acquisition attestations; see the preceding failure-audit report.
- Real historical OOS/walk-forward trade count, hit rate, expectancy, profit factor, Sharpe/Sortino, drawdown, gain/loss, calibration and per-regime performance were **not measured**. Synthetic correctness tests do not establish investment performance.
